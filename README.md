# PMJ Application

A Flutter-based donation management application for a charitable organization. The app has two faces — an **admin** module for managing donors, transactions, and reports, and a **donor** module for donors to view their payment history and submit new payments.

## Tech Stack

- **Flutter** (Dart SDK ≥ 3.5.3)
- **Firebase**
  - `firebase_core` — initialization
  - `firebase_auth` — authentication (admins and donors)
  - `cloud_firestore` — primary data store (donors, transactions, users, config)
- **Cloudinary** — image hosting for donor photos and transaction attachments (see `lib/services/image_upload_service.dart`)
- **State management:** `provider`
- **Local cache / persistence:** SQLite (`sqflite`), `shared_preferences`, `flutter_cache_manager`
- **PDF & sharing:** `pdf`, `share_plus` — for receipts and reports
- **UPI & deep links:** `url_launcher` — for UPI payment intents and WhatsApp/SMS sharing
- **UI:** `flutter_svg`, `shimmer`, `photo_view`, `dropdown_search`, `flutter_typeahead`, `pin_code_fields`, `hugeicons`
- **Other:** `image_picker`, `connectivity_plus`, `uuid`, `intl`

## Features

### Admin module
- **Donor management** — add, edit, list, search donors; photos hosted on Cloudinary
- **Transaction tracking** — log donations with attachments; real-time sync via Firestore
- **Deletion history** — audit trail for deleted donors and transactions
- **Reports** — generate transaction reports and PDF receipts (`pdf` + `share_plus`)
- **UPI payment links** — generate and share UPI payment links via WhatsApp/SMS
- **UPI config** — configure UPI ID and organisation name used for payment links
- **User management** — manage admin users

### Donor module
- Donor login (PIN-based)
- Personal dashboard
- Profile view and edit
- Payment history
- Payment submission flow

### Cross-cutting
- Offline cache via SQLite with sync to Firestore
- Connectivity-aware UI (`connectivity_plus`)
- Shimmer loading states throughout

## Setup

### 1. Prerequisites
- Flutter SDK ≥ 3.5.3
- A Firebase project with **Auth** and **Firestore** enabled
- A Cloudinary account (for image uploads)

### 2. Firebase configuration
Firebase credential files (`lib/firebase_options.dart`, `android/app/google-services.json`, iOS plists) are **not** committed — generate them for your own Firebase project with:

```bash
dart pub global activate flutterfire_cli
flutterfire configure
```

This will regenerate `firebase_options.dart` and place platform config files.

### 3. Cloudinary configuration
Set your Cloudinary upload URL and preset in `lib/config/app_config.dart`.

### 4. Install & run
```bash
flutter pub get
flutter run
```

### 5. Android release signing
The release keystore is **not** committed (intentionally — see `.gitignore`). To build a signed release:

1. Generate or obtain a `.jks` keystore.
2. Create `android/key.properties`:
   ```
   storePassword=...
   keyPassword=...
   keyAlias=...
   storeFile=../my-release-key.jks
   ```
3. `flutter build apk --release`

## Firestore Data Model (high level)

- `donors/{donorId}` — donor profile, contact info, Cloudinary photo URL
- `transactions/{transactionId}` — donation records linked to donor IDs, with attachment URLs
- `users/{userId}` — admin users
- `config/upi` — UPI ID and org name used for payment-link generation
- Deletion-history collections for donors and transactions (audit trail)

## Notes for collaborators

- `firebase_options.dart` is generated — regenerate with `flutterfire configure` if switching projects.
- Build artifacts (`.dart_tool/`, `build/`) and the release keystore are gitignored.
- Image uploads are routed through Cloudinary, not Firebase Storage, even though `firebase_storage` may be listed transitively.
